# IT assets and accounts plan, 2026-11-02

**Goal:** Add an "IT 资产与账号" module to craftos.app that keeps three registers current: (1) company accounts, mailboxes and paid subscriptions, (2) the devices and phone lines each employee holds, and (3) shared office equipment and supplies with stock levels. Employees keep their own entries up to date; IT/admin sees everything and gets reminders.

**Architecture:** Same shape as HR/RMA/WMS: one API module per area (`src/it-accounts.ts`, `src/it-devices.ts`, `src/it-supplies.ts`) with its own schema string, zod input, `deny()` errors, `audit_events` rows and Chinese/English messages; one frontend module per area (`dist/it-*.js` + `it.css`) in the existing workspace shell, both themes and both languages. Holders are Work OS users, so it links to HR profiles (status `leaving` → return list). No new external services.

**Tech:** Node 24, TypeScript, Fastify, PostgreSQL/PGlite, vanilla JS, node:test, linkedom.

---

## Passwords are never stored

The register records *that* an account exists and *where* its password lives, never the password itself.

- Passwords, recovery codes and API keys live in a company password manager (1Password Business or Bitwarden Teams, decided by the owner) in shared vaults per team.
- Each account row has `vault_ref`: a link to the vault item (validated as an https URL). The UI shows an "Open in password manager" button.
- There is no password, PIN, recovery-code or token field anywhere. The notes field shows a warning, and saves are rejected when notes match obvious secret patterns (`password:`, `密码[:：]`, `sk-…`, long base64/hex strings). This is a guard, not a guarantee.
- Payment cards are recorded only as a label plus last 4 digits (`招行公司卡 ****1234`).

## Roles

| Who | How set | Can do |
| --- | --- | --- |
| IT admin | `WORKOS_IT_USER_IDS` (deployment config, Work OS user IDs), same pattern as HR | Everything: all registers, costs, assign/return devices, stock adjustments, reminders, CSV import/export |
| Executive | existing `WORKOS_EXECUTIVE_USER_IDS` | Read everything, including subscription cost totals |
| Manager | existing `manager_id` reporting line | Read the accounts/devices of direct and indirect reports (no costs) |
| Employee | everyone | Own devices and phone lines; accounts they own or use; add an account they use; report a change or problem; confirm the quarterly check; take supplies |

## Phase 1 — Accounts, mailboxes and subscriptions

- `it_accounts`: service name, category (email / SaaS / social / marketplace / cloud / domain / bank-portal / other), login identifier (company email or username), URL, owner (user), `vault_ref`, 2FA method + where it is bound (whose phone / authenticator / hardware key), shared or personal, status (active / to cancel / cancelled), notes.
- `it_account_users`: who else uses a shared account (so leaving people are visible).
- `it_subscriptions` (optional per account): plan, seats, cost, currency, billing cycle (monthly / yearly / one-off), next renewal date, payment label + last 4, auto-renew flag, invoice contact.
- Company mailboxes are accounts with category `email` plus mailbox type (personal / shared / alias / forwarding target).
- Self-service: "我的账号" lists what I own and use; I can add one, edit my own, or flag "I no longer use this".
- Quarterly check (季度确认): every employee gets an inbox task "确认你的账号与设备" on the first workday of each quarter; it lists their rows with "correct" / "needs change" per row and a "I have nothing else" confirmation. IT sees completion % and who is overdue; reminders at 7 and 14 days.
- Reminders to IT (and the account owner): renewal in 30/7 days, auto-renew on a "to cancel" subscription, 2FA bound to someone who is leaving, account owned by someone who is leaving.
- Dashboard for IT/executives: monthly and yearly subscription cost (by category, by currency), upcoming renewals, accounts with no owner, accounts with no `vault_ref`.
- CSV import (with a downloadable template) for the first collection round, and CSV export.
- Tests: role matrix, manager-chain visibility, cost hidden from managers/employees, secret-pattern guard, `vault_ref` validation, renewal reminder dedupe, quarterly check lifecycle, import validation errors per row, both languages.

## Phase 2 — Devices and phone lines

- `it_devices`: asset tag (auto `OL-2026-0001`, editable), type (laptop / desktop / monitor / phone / tablet / headset / keyboard-mouse / other), brand, model, serial / IMEI, purchase date, price, vendor, warranty end, status (in stock / assigned / in repair / retired / lost), location, holder, condition, photos (like RMA photos, 5 per device).
- `it_device_events`: append-only history — purchased, assigned (to whom, by whom), returned (condition, photo), repair out/in, retired, lost.
- Assign/return flow: IT assigns → holder gets an inbox item and acknowledges receipt (签收); return records condition. A device has one holder at a time (409 on stale version).
- `it_phone_lines`: number, carrier, plan, monthly fee, SIM/eSIM, holder, the device it is in, which accounts use it for 2FA (linked from Phase 1), status.
- "我的设备": holder sees their devices and lines, can report a fault or loss (creates an IT inbox item).
- Reminders: warranty ending in 30 days, devices still held by someone whose HR status is `leaving`, unacknowledged assignments after 3 days.
- Label printing: a printable sheet of asset-tag QR codes; scanning one opens the device page.

## Phase 3 — Office equipment and supplies

- Shared office equipment (printers, projectors, routers, furniture) reuses `it_devices` with a location instead of a holder.
- `it_supplies`: item, category (stationery / printing / cleaning / pantry / packaging / IT consumables), unit, on-hand quantity, minimum level, location, preferred vendor, last price.
- `it_supply_moves`: stock in (purchase, with cost), stock out (who took it, how many, why), and stocktake adjustments with a reason; on-hand is derived from moves.
- Employees can record taking supplies (领用) from a phone-friendly page; IT can do a stocktake that shows the difference per item.
- Reminders: item below minimum level → IT inbox with a suggested reorder list.

## Phase 4 — Offboarding and onboarding hooks

- When an HR profile becomes `leaving`, IT gets one checklist: devices and phone lines to return, accounts they own to transfer, shared accounts to rotate the password on (done in the password manager, confirmed here), 2FA to move, mailbox to forward or close. Nothing is changed automatically.
- When HR Phase 3 checklists exist, these items join the offboarding/onboarding templates; for new hires, a "standard kit" (laptop + headset + mailbox + listed SaaS seats) creates the assign tasks.

## Release per phase

Full API and frontend suites, typecheck/build; commit frontend; pin its SHA in `deploy/frontend-revision.txt`; push both only after the user approves; check Render deploy and `/health`. `WORKOS_IT_USER_IDS` must be set in Render by the owner before IT admin features are usable. The password manager is chosen and set up by the owner outside Work OS.
